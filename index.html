Core Capability · AI Platform Architecture

네 계층이 맞물려 움직이는 AI 플랫폼.

Four layers, one platform.

현장 데이터를 표준화하고, 온톨로지로 의미를 붙이고, 알맞은 모델을 고르고, 에이전트가 실행해 서비스로 돌려줍니다. 계층 사이는 MCP와 A2A 표준으로 연결합니다.

서비스는 MCP로 에이전트와 연결되고, 에이전트끼리는 A2A로 일을 나누며, 오케스트레이션 계층의 모델·RAG·온톨로지가 표준화된 현장 데이터 위에서 동작합니다. 계층별 구성은 현장과 요구에 맞춰 설계 단계에서 정합니다.

Safe Execution

AI는 계획하고, 실행은 검증을 통과해야 합니다.

AI plans. Execution passes checks first.

에이전트가 설비와 시스템을 바로 만지지 않습니다. 절차를 먼저 쓰고, 가상 환경에서 돌려 보고, 사람이 승인한 다음에 실행합니다.

  1. 절차 생성

    지시를 받으면 에이전트가 실행할 절차 전체를 정해진 형식으로 먼저 씁니다.

  2. 가상 검증

    디지털 트윈에서 그 절차를 먼저 돌려 보고 설정 범위와 안전 기준을 확인합니다.

  3. 사람 승인

    담당자가 검증 결과를 보고 승인합니다. 휴대폰에서도 됩니다.

  4. 실행·기록

    승인된 절차만 실행되고, 모든 단계가 고칠 수 없는 기록으로 남습니다. 같은 기록으로 다시 판정하면 같은 결과가 나옵니다.

가상 검증 통과와 승인이 둘 다 없으면 시스템이 실행을 거부합니다.AI를 믿는 대신 코드가 막습니다. 숫자 계산과 판정은 코드가, 말과 계획은 AI가 맡습니다.

FAQ

자주 묻는 질문.

카루스웍스는 어떤 회사인가요?

AI 에이전틱 SI 기업입니다. 기업과 기관의 업무 시스템에 AI 에이전트를 설계·구축·연동하고, 운영과 품질 관리까지 한 팀이 맡습니다.

기존 시스템을 바꿔야 하나요?

아닙니다. 쓰고 계신 그룹웨어, 민원·예약·출입·설비 시스템의 데이터를 표준화해 연결하고, 에이전트는 MCP 표준으로 붙입니다.

AI가 잘못 실행하면 어떻게 되나요?

실행 전에 절차를 가상 환경(디지털 트윈)에서 먼저 돌려 보고, 담당자가 승인한 절차만 실행됩니다. 가상 검증과 승인이 없으면 시스템이 실행을 거부합니다.

데이터가 외부로 나가나요?

내부 서버에 소형 모델과 메모리·검색 데이터를 두는 구성을 기본으로 설계합니다. 어떤 일을 클라우드 모델로 보낼지는 도입 설계 단계에서 고객이 정합니다.

특정 AI 모델에 묶이나요?

아닙니다. 일상 업무는 내부 소형 모델이 처리하고, 복잡한 추론만 라우터가 GPT, Claude, Gemini, Llama 같은 모델 중 알맞은 쪽으로 보냅니다. 모델은 바꿔 끼울 수 있습니다.

작게 시작할 수 있나요?

네. 업무 하나와 데이터 하나로 작은 검증(PoC)을 먼저 하고, 효과를 확인한 뒤 넓혀 갑니다.
